Hardware & safety

This system switches a 230 V mains load. It is designed for an isolated project bench with the relay module fed through a fused plug, grounded enclosure and an RCD-protected supply. Only qualified personnel should connect mains wiring.

  • ESP32 dev board — reads sensors and drives the relay.
  • DHT11 — air temperature and humidity.
  • LDR + fixed resistor divider — ambient light on the ADC.
  • Relay module (isolated) — switches the lamp circuit.
  • 230 V bulb — the controlled appliance.

Firebase setup

Create or reuse a Firebase project, enable the Realtime Database, and copy the web app config into dashboard.html at the top of the script. The dashboard requires apiKey, authDomain, databaseURL and projectId; any placeholder value leaves the dashboard in CONFIGURATION REQUIRED state.

Example rules are illustrative. Configure security rules to expose only the paths this device needs.

ESP32 device workflow

  1. Boot and connect to Wi-Fi.
  2. Authenticate with Realtime Database credentials.
  3. Publish sensorData each cycle and push a logs entry.
  4. Listen on control/bulbState and settings/.
  5. In AUTO, raise the relay when LDR < ldrThreshold, otherwise lower it.
  6. In MANUAL, mirror control/bulbState to the relay.
Device code is out of scope for this dashboard. Screenshots and a walkthrough video will be embedded here when available.

Known issues & troubleshooting

Open index.html and sign in with your Google account. The dashboard requires Firebase Authentication. If sign-in fails with operation-not-allowed, enable Google sign-in in Firebase Console → Authentication → Sign-in method.

Check internet access and Firebase availability. For the ESP32, confirms it wrote sensorData/timestamp within the last 90 s; otherwise the expected ONLINE / STALE / OFFLINE logic will not clear.

The command only updates control/bulbState. The device must be running and subscribed to that path to drive the relay. If it is offline no physical change occurs — this is the intended, honest behaviour.

Charts render only from real logs/ records. If the device has not published yet, the panels remain empty by design. Blocked CDNs also leave analytics unavailable.
